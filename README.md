# phenorelay: crop phenology observation network for Asia

A community-supported network for observing crop phenology (bud burst, flowering, ripening, heading, harvest) of
**fruit crops and field crops across East, Southeast and South Asia**, with farmer observation guidelines in Asian
languages.

phenorelay does not aim to be a separate research database. It helps growers, especially in rural communities that
take little part in existing reporting programmes, record consistent observations. It then verifies those records and
relays them, together with the raw data behind them, to established research platforms. The website's own database
organizes, checks and distributes contributed records.

## Design principle

Form follows function. The site uses a plain, old-style scientific database layout: system fonts, bordered tables,
query forms, permanent query URLs, record pages, a field dictionary, CSV export and printable sheets. There is no
framework and no build step for the pages. Everything works from static files, on GitHub Pages, or opened locally
from disk. Pages work on phones, so farmers can use them in the field.

## Contents

The main menu has four buttons. Each section has a short row of sub-links.

| Menu | Path | Purpose |
|---|---|---|
| **Team** | `team.html` | Core team, advisors, partner organizations, contributors |
| **About** | `about.html` | About Us (limitations, solutions, impacts), scope, network, roadmap, how to join |
| **How to Use** | `how-to.html` | Two buttons: Organization or Individual |
| | `org.html` | Organization path: organization code + observer ID, for observers trained by their organization |
| | `individual.html` | Individual path: start → lessons → quiz → consent, then recording |
| | `guidelines/` | Farmer guideline PR-G-01 in `en` (reference), `ko`, `ja`, `zh-hans` (drafts) + translation status |
| | `stages.html` | BBCH stage scales, thresholds, management events |
| | `submit.html` | Recording form, open only after one of the two paths (offline queue, GPS button, CSV download) |
| **phenorelay** | `index.html` | Database overview: quick search, contents, records by country |
| | `search.html` | Query form; record list, summary by year, summary by site with trend; CSV export |
| | `record.html?id=…` | Single record view, same stage in other years, all stages that season |
| | `crops.html` | Crop reference list (EN / KO / JA / ZH names, scientific name, stage scale) |
| | `data.html` | Downloads, field dictionary, Darwin Core mapping, QC, privacy, licence |

| Path | Purpose |
|---|---|
| `data/reference.json` | **Single source** for crops, stage scales, countries, guideline languages, organization codes |
| `data/observations.csv` | Observation records (currently **synthetic demo data**) |
| `tools/build_data.py` | Builds `data/reference.js` and the demo observation files |
| `assets/notice.js` | Site-wide announcement popup, shown once per visitor. Edit `ID`/`TEXT` to post a new one; set `ID` to `""` to turn it off |
| `tools/stamp_layout.py` | Stamps the shared masthead, menu and footer into every page |

## Working on the site

```sh
# after editing data/reference.json (or the demo generator)
python3 tools/build_data.py

# after adding a page or changing the menu, sub-links or footer in tools/stamp_layout.py
python3 tools/stamp_layout.py

# preview
python3 -m http.server 8000   # then open http://localhost:8000/
```

New pages need `<!--#masthead--><!--/masthead-->` and `<!--#footer--><!--/footer-->` markers and an entry in
`SECTION_OF` in `tools/stamp_layout.py`. Guideline documents also carry `<!--#langbar--><!--/langbar-->`.

## Demonstration data

`data/observations.*` contains **synthetic records** (status `DEMO`) generated by `tools/build_data.py` so that the
search, record and export functions can be tested. They are not real observations and must be replaced before
any public data release.

## Adding a guideline translation

Copy `guidelines/en.html` to `guidelines/<code>.html`, translate it, keep section numbers and BBCH codes, set the
language's `status` and `file` in `data/reference.json`, then run both tools. See `guidelines/index.html`.
